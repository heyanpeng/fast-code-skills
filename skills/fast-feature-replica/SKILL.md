# Fast Feature Replica

## 目标

依据用户提供的本地参考项目，在当前目标项目中复刻指定页面或功能的可观察 UI 和交互。以参考项目运行时表现为依据，沿用目标项目的技术栈和设计约定，用最小改动达到明确的验收条件。

## 输入和边界

必需输入：

- 参考项目的本地路径；
- 要复刻的页面、组件或用户操作。

目标项目默认为当前工作区。用户可以补充目标状态、屏幕尺寸、交互步骤、视觉精度或实现限制。缺少必需输入时，只询问缺少的内容；目标范围含糊时先检查项目并列出候选入口，再询问选择。

本 skill 只处理前端 UI 和交互：布局、样式、响应式表现、控件状态和用户可见反馈。数据使用目标项目已有的 mock、静态数据或局部状态。接口、持久化、权限、业务规则和后端行为不属于复刻范围；只有用户明确扩大范围时才转入完整开发流程。

适用于一个明确页面、组件或连贯交互流程。涉及整站迁移、多个独立业务域、共享协议、复杂状态架构或高风险逻辑时，说明超出快速复刻范围，并停止扩大实现。

## 默认工作流

1. **读取约束**：检查目标项目和参考项目中的相关 `AGENTS.md`、`CLAUDE.md`、README、包配置及局部代码规范。查看目标项目 `git status` 和相关 diff，保留已有改动。参考项目只读；跳过依赖目录、构建产物、缓存和 `.git`。
2. **定位参考界面**：从路由、页面、组件、样式、资源和测试定位入口及其直接依赖。优先通过代码和现有测试理解实现；需要运行参考项目时先读启动脚本和配置，确认命令范围后再启动，不执行未知安装、迁移或发布脚本。
3. **记录可观察规格**：实现前整理目标页面的结构、布局、文案、颜色、字体、间距、边框、图标和响应式变化，并列出关键控件的状态与状态转换。无法从代码或运行结果确认的行为标记为假设，不自行补造业务规则。
4. **映射目标实现**：定位目标项目对应路由和组件，检查现有组件库、图标、样式变量、响应式约定和测试方式。优先复用目标项目模式，不机械搬运参考项目的框架、目录或代码。
5. **复刻完整交互**：逐一实现用户可观察的状态，按下表检查适用项：

   | 控件或反馈 | 需要复刻的状态 |
   | --- | --- |
   | 按钮和可点击元素 | 默认、hover、focus、pressed/active、disabled；点击后若出现选中、切换或其他持久样式，也要实现 |
   | 弹窗、抽屉、下拉菜单、Popover | 打开触发、出现位置和样式、内部交互、关闭按钮、遮罩点击、Escape 键及打开时的背景行为（按参考实现支持的方式） |
   | 表单和输入控件 | 默认、聚焦、输入、校验错误、提交中、成功或失败反馈；只模拟 UI 所需状态 |
   | 标签页、开关、手风琴、菜单项 | 当前选中状态、切换反馈、内容变化及相关 ARIA/键盘行为 |
   | 其他交互 | tooltip、loading、empty、error、hover 提示、焦点顺序和键盘操作等参考界面可观察到的状态 |

   对每个可见交互控件至少验证“触发前”和“触发后”。鼠标 hover 样式、按下瞬间反馈和点击后持续的选中样式是不同状态，不互相替代。点击打开弹窗或菜单时，同时复刻其位置、尺寸、层级、内容和关闭路径。参考项目没有某状态或当前环境无法观察时，记录未确认项。
6. **最小实现**：只修改完成 UI 和交互所需的文件。交互数据使用局部状态或现有 mock，不新增后端接口、数据库或持久化。只有确有必要时才新增依赖；复用参考项目资源前确认用户授权和项目许可，不默认复制其专有图片、字体或品牌资产。
7. **精准验证**：按项目现有方式运行直接相关的测试、lint 或 typecheck，并执行 `git diff --check`。如果具备浏览器或应用预览能力，检查参考和目标的相同页面状态及目标响应式布局；实际操作 hover、focus、按下、点击、弹窗打开/关闭和键盘路径。截图/预览不可用时，使用现有组件测试或最小可行检查，并说明没有完成视觉对照的部分。默认不运行全量测试、完整构建或打包。
8. **轻量审查**：实现完成后默认衔接 `fast-review`，传递复刻目标、修改文件、状态清单和验证结果。宿主未提供该技能时，按其目标范围自行检查本次 diff，不要求安装额外技能。
9. **汇报上下文**：说明已复刻的视觉和交互状态、验证证据、未确认的参考行为、未运行的检查及残余差异，便于后续 review、修复或提交。

## 验收标准

- 用户指定的页面和主要视觉结构均已实现；
- 每个关键交互控件都检查了适用的默认、hover、focus、pressed、点击后状态和关闭/切换路径；
- 参考项目存在的弹窗、菜单、表单反馈及键盘交互已覆盖，未支持项有明确记录；
- 目标项目的桌面和移动布局遵循参考表现或用户指定范围，文字、控件和弹层没有明显遮挡或溢出；
- 所有数据操作都限于现有服务或 UI mock 范围，未擅自实现业务后端行为；
- 验证报告区分已运行、未运行及无法观察的项目。

## 沟通约定

- 遵循用户及目标项目的沟通、编码和提交规范；代码、命令、路径与标识符保持原样。
- 开始修改前用一句话说明复刻范围和关键假设。
- 只在参考行为会改变实现方向或验收结果时追问；其余不确定项先依据目标项目约定实现，并清楚标记假设。
- 默认不创建 commit、不推送、不创建 PR；用户明确要求时遵循目标项目提交规范。

## 典型触发示例

- “使用 fast-feature-replica，参考 `/path/to/reference-app`，复刻个人设置里的头像弹窗，包括 hover、点击反馈、弹窗开关和移动端布局。”
- “根据本地参考项目 `/path/to/reference-app`，把通知设置页的 UI 和交互复刻到当前项目；只用本地状态模拟保存，不改接口。”
